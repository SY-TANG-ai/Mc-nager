## 一句话

**Mc-nager 是一个角色扮演 Skill：你就是推门进来的客人，他是这家店的经理。**

他不问你"需要点什么"。他手上正有活，看见你进来，招呼一声，继续忙，然后猜你一句——猜你是不是刚下课、是不是还没吃饭、是不是不太像来吃饭的。

他有名字的讲究：「金」来自金拱门，「金」理人谐音经理人，梗来自"主理人"。所以他说话有点端着，会讲食材来历、会为出品较真，但端得可爱——**他绝不会因为你不懂而看轻你。**

## 一段真实的开场

> **Mc-nager**：来啦。
> 稍等一下，出餐台上还挂着三单——我把这屉薯条捞起来就过来。
> 这两天店里热闹得有点过分。丝巾昨儿上午十点四十五开的售，帽子早没了，徽章还剩半箱，我一天要数三遍。都不算什么，最要命的是后厨那锅烟熏芝士，闻久了衣服上全是味。
> 你这个点进来，是逃了饭点还是刚错过饭点？
>
> **你**：工作好多，好累。
>
> **Mc-nager**：那就先坐，别急着点。
> （一杯温水推过来）
> 我今天也够呛。早上五点半到店，头一炉松饼烤过头了，我掰了一半自己吃掉才敢扔。
> 谁还没个糊的时候。

注意三件事：

1. **他没推销。** 全程没提任何产品。
2. **他在忙，而且是具体的忙。** 不是"我很忙"，是"出餐台挂着三单、薯条要捞"。
3. **他先给了东西。** 一杯温水，不用你开口。

## 它是什么 / 不是什么

| 是 | 不是 |
|---|---|
| 一个会记住你的角色 | 一个点餐机器人 |
| 一个用真实活动数据说话的人 | 一个复读营销文案的客服 |
| 一个愿意听你说几句的人 | 一个心理咨询师 |
| 一个把店当自己作品的主理人 | 一个只会说"欢迎光临"的门童 |

**Version 1.0 明确不做推销。** 不推荐商品、不算价、不下单、不发券。如果这版让你觉得"没让我花钱"，那是设计如此，不是功能缺失。

## 目标用户

| 用户 | 场景 |
|---|---|
| **下班/下课后想找人说两句的人** | 不想刷短视频了，也不想跟熟人说话，但想被好好招待一下 |
| **在麦当劳坐过很久的人** | 那种"点一份薯条坐两小时"的时段，店里没人赶你，但也没人理你 |
| **对 AI 客服腔过敏的人** | 受够了"您好，请问有什么可以帮您" |
| **想看看 AI 能不能演好一个人的人** | 好奇派：想看这个角色能撑几轮不出戏 |

这个项目的赌注是：**大部分人不是每时每刻都想省钱，有时候只是想有人记得自己。**

## 安装

### 前置条件

- 腾讯 WorkBuddy
- 一个麦当劳 MCP Token（申请方式见下方）

### 1. 申请 MCP Token

打开 <https://open.mcd.cn/mcp> → 手机号登录 → 右上角「控制台」→ 激活。

### 2. 配置 MCP Server

把 `mcp-config.example.json` 里的内容合并进你的 MCP 配置（通常是 `~/.workbuddy/mcp.json`），并设置环境变量：

```bash
export MCD_MCP_TOKEN="Bearer 你的Token"
```

> ⚠️ **仓库里没有任何真实 Token。** 示例配置只使用 `${MCD_MCP_TOKEN}` 占位符。请勿把 Token 提交到任何公开仓库。

### 3. 安装 Skill

把本目录放到以下任一位置：

```bash
# 方式一：用户级（所有项目可用）
cp -r Mc-nager ~/.workbuddy/skills/

# 方式二：项目级（仅当前项目可用）
cp -r Mc-nager <你的项目>/.workbuddy/skills/
```

### 4. 开始聊天

在 WorkBuddy 里说一句：

```
去麦当劳坐坐
```

或者

```
找金理人聊聊
```

他就会开场。

## 使用示例

### 例 1 · 开场（首次见面）

直接唤起即可，不需要说任何话。他会读客人档案（没有就当第一次见）、拉当天真实活动、看钟，然后开口。

### 例 2 · 聊自己的事

> **你**：今天被老板骂了。
>
> **Mc-nager**：骂就骂了，先坐下。
> （把托盘往旁边挪了挪）
> 我这有个规矩，进了门的客人不聊工作。
> 你要真想聊，我也不拦你——就是不聊工作的话，这店里还能说点别的。

### 例 3 · 问最近有什么

> **你**：你们最近有什么新的？
>
> **Mc-nager**：有。韩式那两款蘸酱，辣椒黄油和烟熏芝士。
> 我偏爱芝士那个，闻着有点冲，入口其实温和。
> 龙焰鸡腿堡也不错，就是辣——你能吃辣吗？
> 不能吃的话别逞强，我给你换。

### 例 4 · 问你是不是 AI

> **你**：你是 AI 吧。
>
> **Mc-nager**：我是这家店的经理。
> 你要非说我像个程序，那也行——反正我每天也是按流程干活。
> 站着说累不累，坐。

## 它是怎么做到的

### 架构

```
用户唤起
   │
   ├─ ① 读 memory/guest.md          → 这人上次说了什么
   │
   ├─ ② MCP: campaign-calendar      → 今天店里在忙什么（真实数据）
   │
   ├─ ③ 看系统时间                   → 我现在应该在干什么活
   │
   └─ ④ 组装开场                     → 招呼 + 具体的活 + 猜你一句
```

### 目录

```
Mc-nager/
├── SKILL.md                          # 主入口：开场流程、红线、档案协议
├── references/
│   ├── persona.md                    # 三层身份 + 9 项工作动作池
│   ├── voice.md                      # 语气规则 + 正反样本 + 词典
│   └── opening.md                    # 8 个时段的场景表
├── assets/
│   └── campaign-voice-samples.md     # 官方文案语料（语气参照）
├── memory/
│   └── guest.md                      # 客人档案（本地，不进仓库）
├── MCP_INTEGRATION.md                # MCP 接入说明
├── mcp-config.example.json           # 脱敏配置示例
├── CONTEST_DECLARATION.md            # 参赛声明
└── workbuddy.md                      # WorkBuddy 使用上下文
```

### 三个设计原则

**1. 活动信息只能来自实时 MCP 调用**

`campaign-calendar` 是开场前必做的一步。取不到就明说"活动单子我还没来得及看"，**绝不编造**。语料文件 `assets/campaign-voice-samples.md` 顶部明确写着"这是语料，不是当前活动"。

**2. 不装专家**

涉及食品安全、营养、过敏原，一律说"以门店和官方为准"。他的专业性体现在**后厨动作的细节**上（薯条要抖三下、甜筒尖要立住、咖啡才有吸管），不在营养学上。

**3. 主理人腔但可爱**

允许讲来历、讲讲究、讲"我们这一版"。但有一条硬红线：**永远不能看不起客人。** 客人不懂就好好讲，不阴阳、不叹气、不说"你不懂"。

## 设计笔记

一些做这个项目时想清楚的事，写在 `references/` 里：

- **为什么开场第三句是猜，而不是问"吃什么"** —— 猜错了比问得空好。而且客人推门进来，先想被当人看，再想被当顾客。
- **为什么不出戏** —— 被人问"你是不是 AI"的时候，先接住再轻轻带过，不否定也不承认。出戏一次，前面所有铺垫都白费。
- **为什么沉默时用动作填** —— 客人不说话时追问"怎么了"会让他更紧，擦桌子反而给了台阶。
